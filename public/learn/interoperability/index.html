Using AyFlux results with CSV, R, PK-Sim, and MoBi

Export simulated concentration–time profiles for analysis and comparison outside AyFlux.

Import a spreadsheet into AyFlux Research tools

Research tools → Compare an external PK-Sim / MoBi CSV accepts CSV files up to 4 MB. To use an XLSX workbook, open it in Excel or LibreOffice, select one worksheet with time and concentration values, and save that worksheet as CSV. In AyFlux, choose the CSV, select the time and concentration columns, confirm their units and the target analyte, then choose Compare curves. Run an AyFlux simulation first. Import compares concentration curves; it does not import a model or change model parameters.

Excel export for PK-Sim and MoBi

Choose Export results → PK-Sim / MoBi (.xlsx) above the simulator charts. The workbook contains one sheet per scenario and analyte, with numeric time and median predicted concentration, units in the headers, and explicit simulated-data labels.

In PK-Sim or MoBi, use Add Observed Data to import the workbook as comparison data. Map Time to time (h) and Concentration to measurement (mg/l), then confirm molecule and compartment metadata. Time and concentration are the only numeric columns on each worksheet. Leave the Error field empty. For older workbooks, clear any automatic assignment of molecular weight to Error. If a molar unit conversion is needed, use 225.21 g/mol for acyclovir or 239.19 g/mol for CMMG. Despite the importer's name, these are simulated predictions, not patient measurements. Uncertainty bounds are omitted because they are not measurement standard deviations.

In a Windows import test with MoBi 12 Update 3, the saved project retained all 385 no-dialysis plasma acyclovir values from a previous workbook after clearing the Error mapping. Across 0–96 h, absolute differences from the workbook were below 0.000002 mg/L.

An XLSX file does not contain a runnable PK-Sim/MoBi model. Native .pkml simulation export requires a model built in OSP. OSP also supports PKML data sets, which are distinct from simulation models. See the OSP data import documentation.

Export results from AyFlux

On the simulator's Concentration tab, open the single Export CSV… dropdown and choose Detailed results for AyFlux's wide-format data, or R / OSP tidy for the long-format CSV. Selecting an option starts the download with time in hours, scenario, analyte, model statistic, concentration in mg/L, and interval coverage.

The tidy file includes plasma and CSF acyclovir, plasma and CSF CMMG, and modeled lower, median, and upper curves across scenarios. Each concentration is a model result, not a patient measurement.

Compare external CSV directly in AyFlux

Open the simulator's Research tools tab, import a PK-Sim or MoBi results CSV, and choose its time and concentration columns and units. AyFlux draws the two concentration curves together, plots their difference, and reports curve-to-curve error metrics. Imported data remain in the browser. This is not native model import or clinical validation.

Read and compare in R

Use the AyFlux R example to read one scenario and compare it with a time series exported by PK-Sim or MoBi. It uses base R and asks you to choose the exact OSP columns and units rather than guessing.

source("interop/ayflux_compare.R")
ayflux <- read_ayflux_curve("ayflux_results_tidy.csv",
                            scenario = "Intermittent HD")
plot(ayflux$time_hours, ayflux$concentration_mg_L,
     type = "l", xlab = "Time (h)", ylab = "mg/L")

What works with PK-Sim and MoBi?

Open Systems Pharmacology tools can export model results as CSV. You can compare those results against AyFlux in R after matching time, concentration units, dosing, dialysis settings, and sampling compartment.

Before comparing models

  • Use the same drug, administered dose and route, and simulation timeline.
  • Check whether values are in mg/L, µg/mL, or a molar unit before comparing them.
  • Match plasma with plasma. Do not treat a CSF or CMMG curve as equivalent to a plasma acyclovir curve.
  • Account for differences in kidney function, dialysis scheduling, and model structure.
  • Recognize that agreement between two models is not independent clinical validation.

For more detail, see PK-Sim's import/export documentation and the OSPSuite-R project.

Independent R model comparisons

AyFlux now provides two optional, documented research workflows. The first uses mrgsolve to implement AyFlux's IV acyclovir/CMMG compartment equations independently and compare deterministic predicted curves, including a changing CrCl example. The second uses OSPSuite-R to run the official Aciclovir PBPK example and export its plasma curve with explicit concentration and time units.

They serve different purposes: the mrgsolve exercise checks code/solver agreement, while the OSPSuite example compares a different model structure. Neither establishes clinical validation, and OSPSuite's built-in example is not guaranteed to match AyFlux's route, administered dose or simulated individual. OSPSuite-R must be run in a supported local environment; the browser does not run R packages directly.

Read the comparison guide and runnable R scripts. The model equations and parameter provenance are available in the Methods guide.
